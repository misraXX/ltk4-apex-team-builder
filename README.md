# LTK4 APEX TEAM BUILDER

LTK4参加者60人のAPEXカスタム用チーム編成ツール。白系のLTK4デザインと人物アイコンで、出欠・戦力・IGL・知り合い条件・当日の組み合わせを確認できます。

## 運営者の使い方

1. 公開URLを開き、受け取った運営用パスワードを入力します。
2. 「メンバー管理」で欠席者を外し、APEXの到達ランクとIGL適性を設定します。
3. 「関係性の設定」で、必要な人に「最低1人は必要」「できれば一緒」と相手候補を指定します。
4. 「自動チーム分け」を押します。ランクごとの固定点を合算して編成し、チーム合計を表示します。実績未確認の人は2点です。
5. メンバーを1人選び、別のチームの人を選ぶと交換できます。「元に戻す」で取り消せます。
6. 実際に使用する編成を「このマッチを確定」で履歴に残します。その後「次のマッチを編成」を押します。

知り合い必須の条件に違反する案は確定できません。解を見つけられない場合は、候補を増やすか手動調整してください。探索方式のため全条件の最適解を保証するものではありません。

## 設定を2人で受け渡す

設定は使っているブラウザのlocalStorageに保存されます。「設定を書き出す」でJSONを渡し、相手が「読み込む」を使います。読込時は現在の設定全体を置き換える確認が表示され、直後はUndoで戻せます。

**別端末間の自動同期・同時編集の自動結合はありません。** 一方が編集して書き出し、もう一方が読み込む順で運用してください。GitHub Pagesの同じURLを開くだけでは、他の人の設定は反映されません。

ブラウザの閲覧データ削除や別プロファイルでは保存が引き継がれません。イベント前後に書き出しをおすすめします。「当日の履歴をリセット」では評価・関係性・出欠を残して履歴と現在案を消します。Undoも可能です。

## 簡易パスワード

本人指定の、HTML/JavaScriptによる簡易ロックです。ソースを調べれば回避できる前提で、暗号化・厳密な2人限定・機密保護は行いません。入力した評価や関係性をサイトへ自動送信する処理はありません。Cloudflare・Firebase・外部DB・外部認証は使いません。

パスワードはSHA-256で比較します。変更する場合は `site/app.js` の `PASSWORD_HASH` を新しい値に更新して再公開します。初期パスワードは納品時に別途伝えます。

## 開発と公開

ビルド・依存ライブラリは不要。Node.js 22以上で以下を実行できます。

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run serve
```

ローカルプレビューは `http://127.0.0.1:4178/`。GitHub Actionsは構文・編成・データのテストを実行します。公開対象はsite/だけを抽出したgh-pagesブランチで、GitHub Pagesのソースをgh-pagesのルートに設定します。変更をコミット後、node tools/publish.cjsで再検証して公開ブランチを更新できます。公開ビルドの完了も確認してください。

`site/roster.js` と同梱人物アイコンは既存LTK4資料から抽出しました。公開活動名・LTK所属の参考データであり、APEX戦力・IGL・私的な関係性を推測していません。既存資料とsourcesは変更していません。生成元の確認情報は `docs/roster-source.json`、補助抽出スクリプトは `tools/extract-roster.cjs` です。抽出スクリプトの再実行には元の隣接BPプロジェクトが必要ですが、ツールの起動・公開には不要です。

仕様と検証の記録は `docs/design.md`、`docs/task-board.md`、`docs/cycle-report.md`、`docs/codex-report.md` を参照してください。

公開URL: https://misraxx.github.io/ltk4-apex-team-builder/

## ランク・他FPS実績と固定ポイント

APEXの到達記録24人に加え、全60人の他FPS競技歴/上位ランクを145検索と資料照合で確認しました。他FPS元プロ6人、上位実績17人を記録。そのうちAPEXの配点を上回る9人に他FPS区分を採用し、合計32人の根拠を確認、28人は実績未確認です。現在の実力ではなく過去の確認実績です。

| 区分 | 点 |
|---|---:|
| 元APEXプロ | 10 |
| APEXプレデター | 8 |
| APEXマスター / 他FPS元プロ | 7 |
| APEXダイヤ / 他FPS最高帯 | 6 |
| APEXプラチナ / 他FPSマスター相当 | 5 |
| APEXゴールド / 他FPSダイヤ相当 | 4 |
| APEXシルバー | 3 |
| APEXブロンズ / 実績未確認 | 2 |
| APEXルーキー | 1 |

APEXと他FPSの高い方を初期値に採用し、同点はAPEXを保持します。LoL・TFT・格ゲーのプロ歴やランクは対象外。元プロは単にプロチーム所属というだけでは採用しません。例：mittiii/Zerost/じゃすぱー7、Yutapon/MOTHER3/春茶6、ごんかね5。根拠は各人の詳細でAPEX実績と他FPS実績を分けて確認できます。

他FPSの最高帯はVALORANT Radiant、OW Grandmaster/Top500、CSGO Global Elite等。マスター相当はVALORANT Immortal/Ascendant、ダイヤ相当はVALORANT Diamond等です。ランク制度のない旧FPS/TPSの公式全国優勝は最高帯相当。現在の能力やプロ契約は推測しません。

v5別キーへ確認付きで移行し、旧v1〜v4を残します。実績未確認を2へ変更し、「調査済みの他FPS実績を反映」がONなら高い区分を採用。OFFは既知手動区分を保持。出欠・IGL・組織・候補・メモ・現在案・過去履歴は保持します。旧履歴の未確認5点と合計は当時のまま「旧基準」と表示し、新履歴だけ新配点を使います。

新規利用は調査値が初期値。「調査値を反映」は未確認/空欄のみ補完し、既知の手動区分を上書きしません。区分を手動変更すると固定ポイントも変わります。点数のない人はいませんが、未確認2点は本人指定の基準であり実力を確認した値ではありません。

資料：docs/public-research.json、fps-research-{a,b,c}.json、過去APEX追調査rank-followup-{a,b,c}.json。原映像未視聴・取得制限・根拠不十分な情報も採否理由に残しています。APEX画像8種の元URL/座標/SHA/権利はdocs/rank-icon-sources.json。他FPS区分には一般的な照準/王冠アイコンを使い、APEXの公式バッジと区別します。

過去LTK同チームはLTK1〜3、現在LTK4同チームは別条件です。所属チームと同階級を区別した参加歴を表示します。組織不明・旧所属を現在の同組織条件に含めません。個人の必須候補指定は最優先です。

調査の詳細: docs/public-research.json。公開用: site/research.js と site/ltk-relations.js。変更したローカル設定を公開サイトへ送信する処理はありません。
