# Codex実装指示書

このテンプレートは、ltk4-apex-team-builder でCodexに実装を依頼するときの標準フォーマットです。

`docs/ai-development-rules.md` の「Codex × ChatGPT 併用開発運用ルール v2」に従い、ChatGPTまたは人間が仕様化してからCodexへ渡してください。

## 前提

- 対象プロジェクト: ltk4-apex-team-builder
- 目的: LTK4参加者60人のAPEXカスタムを、出欠・手動10段階評価の合計点・IGL適性・個別の知り合い条件・当日の編成履歴を考慮して編成する。
- 技術構成: ビルド不要のHTML/CSS/JavaScriptによる静的サイト。GitHub Pagesで公開。ブラウザ保存とJSON入出力は提案中で、本人確認が完了するまで実装しない。
- MVP範囲: ホストを使う人が60人の評価・IGL・関係性・出欠を編集し、自動編成、手動調整、マッチ確定、次マッチ編成を行える。合計点とIGL人数と条件の未達を確認できる。白系LTK4デザイン、人物アイコン、日本語UI、レスポンシブ。

## 注意

- Codexは判断者ではなく、実装・検証・差分報告の担当です。
- 最終判断と責任は人間が持ちます。
- 既存の `AGENTS.md`、`docs/design.md`、`docs/ai-development-rules.md` を確認してから作業してください。
- 設計書と矛盾する場合は、実装せず停止してください。

## 設計書チェック

実装前に以下を確認してください。

1. 今回の変更は `docs/design.md` に書かれているか。
2. MVP範囲と矛盾していないか。
3. 今回やらないことに該当しないか。
4. 入力仕様、出力仕様、保存方式、データ構造に影響しないか。
5. 外部API、DB、GAS、サーバー、認証、課金、通知、権限、個人情報に関係しないか。
6. 設計書や変更履歴の更新が必要か。

## 目的

ここに今回の作業目的を書いてください。

## 今回のゴール

ここに完了状態を具体的に書いてください。

## 今回やること

- ここに実施対象を書いてください。

## 今回やらないこと

- ここに対象外を書く。
- 対象外を完了扱いしない。

## 受け入れ条件

- 何ができれば完了かを書く。
- 生成・変更されるファイルを書く。
- 確認すべき動作やテストを書く。
- 人間確認が必要な項目を書く。

## 実装内容

ここに実装方針、変更対象、制約を書いてください。

## UI仕様

UIがある場合は、画面、操作、状態、文言、レスポンシブ確認を記載してください。

UIがない場合は「UI変更なし」と書いてください。

## 処理ロジック

処理手順、入力、出力、エラー処理、既存データ保護方針を書いてください。

## セキュリティ確認

- APIキー、Webhook、トークンなどの秘密情報を追加しない。
- 秘密情報をログ出力しない。
- 個人情報を不要に保存・表示しない。
- 権限や公開範囲を広げる変更がある場合は必ず報告する。
- 外部通信を追加する場合は実装前に確認する。

## 既存機能への影響

- 既存コマンド、既存オプション、既存出力、既存データに影響があるかを書く。
- 影響がある場合は、影響範囲と戻し方を書く。

## テスト・確認項目

- 構文チェック。
- 既存テスト。
- 正常系。
- 異常系。
- 既存出力先の上書き防止。
- 未置換プレースホルダー確認。
- READMEや設計書との整合。

実行できない項目は、理由つきで「未確認」と報告してください。

## 3回セルフチェック

1. v2ルールが、ChatGPT側とCodex側の共通認識として機能するか。
2. 既存の安全停止ルール、設計書チェック、テスト観点を壊していないか。
3. 今回やること以外の大規模改修を混ぜていないか。

## docs/codex-report.md の更新

作業完了後、`docs/codex-report.md` の最新レポートを更新すること。

最新レポートには、必ず以下の `codex-meta` を含める。

```yaml
codex-meta:
  projectId: "ltk4-apex-team-builder"
  status: "completed | in_progress | blocked | failed"
  humanCheckNeeded: true
  designUpdateNeeded: false
  blocked: false
  nextHumanAction: "次に人間が確認・判断すること"
  nextCodexAction: "次にCodexへ依頼するとよいこと"
```

その下に、通常の最終報告をMarkdownで記載すること。
