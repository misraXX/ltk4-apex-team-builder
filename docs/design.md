# LTK4 APEX TEAM BUILDER 設計

更新: 2026-11-24。採用構成: GitHub Pages＋HTML/JavaScript簡易パスワード＋ブラウザ保存＋JSON受け渡し。

## 目的と対象

LTK4参加者60人のAPEXカスタムのチーム編成を支援する。依頼者が初期情報を集め、ゆふなさんが詳細設定と当日運営を行う。

## 本人の決定

- 戦力は厳密なランク推定ではなく、手動の1〜5段階。その合計点で公平さを整える。
- IGL適性を点数とは別に設定する。
- 知り合いが必要な人と不要な人がいるため、個人ごとに事前設定する。
- 当日の同じ人同士の固定を減らす。手動で入れ替えられ、出席確定後に自動編成できる。
- 欠席を反映し、人数が割り切れない場合は2人チームを作る。
- UIは既存LTK4の白系画像と統一し、人物アイコンで見やすくする。
- 公開先はGitHub Pages。Cloudflareは使わない。
- 最新の本人指示「普通にHTMLでパス」「簡単に開くやつでOK」に従い、回避できる簡易ロックを採用する。厳密な2人限定・暗号化・外部認証は行わない。

## 初版の保存と共有範囲

設定はlocalStorageのltk4-apex-team-builder:v2へ保存（旧v1は移行確認後も保持）。簡易ロックの解除はsessionStorageに保持する。JSONで全設定を書き出し・読み込みできる。外部DB・サーバーAPIは使わない。

2人の自動同期・同時編集の自動結合は未対応。要求を完了扱いにせず、設定ファイルの受け渡しで補助する。UIとREADMEと納品時に明示する。Cloudflare/Firebase案は不採用であり、外部リソースは作成していない。

ローカル設定・バックアップ・検証用ファイルをリポジトリと公開成果物へ含めない。GitHub Actionsはテストを実行し、site/だけを抽出したgh-pagesブランチをGitHub Pagesの公開ソースとして使用する。入力内容を外部へ送信しない。公開コード・名簿・画像は簡易ロックを回避すると取得できる前提。

## データと初期値

既存LTK4資料から公開活動名・ID・所属・階級・ロール・人物画像を抽出。名簿は60人でIDは一意、4所属各15人。元データと既存アプリは変更しない。APEX実績と所属組織は60人全員を公開Webで調査。24人に出典付き仮評価、36人は情報不足で未評価。IGLは一次根拠がある1人だけをありとし、私的な知り合い条件は自動で設定しない。

未評価は計算時のみ仮3点を使用し、画面に仮と明示する。知り合いは複数人の指定が可能。所属は緩い優先条件として参照するが、所属だけで私的な親しさを確定しない。

## 編成と手動調整

- 対象は出席者2〜60人。基本3人組で1人組は作らない。59人なら3人19組＋2人1組、58人なら3人18組＋2人2組。
- 2人チームも同じ合計点を目指す初期方針。戦力合計の分散・IGL偏り・知り合いの希望・所属・当日のペア履歴を評価する。
- 必須の知り合い条件を最優先し、違反案は確定できない。出席する相手候補がいなければ生成を止めて表示する。
- 複数の初期配置から探索し、単独交換とペア交換で改善する。全組み合わせの最適解保証はしない。候補が見つからない場合は探索失敗と表示し、必須条件は勝手に解除しない。
- 個人の「最低1人は必要」は指定した相手のうち1人が同チームにいる条件で、相手側の逆指定は不要。
- 自動生成・再生成は主催者の操作で実行する。出欠を変更しただけで既存案を勝手に組み替えない。
- 別チームの2人を選択して交換。合計点・IGL人数・未達条件を更新し、Undoできる。
- 試行案は履歴へ数えない。確定したマッチのみ、評価・IGLを含むスナップショットとして保存する。二重確定を拒否する。
- 確定後の画面と履歴は確定時の評価・IGLを使用し、現在の設定変更で過去記録を変えない。
- 当日の履歴をリセットすると履歴と現在案を消す。評価・関係性・出欠は保持し、確認とUndoを用意する。

## 入出力と異常系

version=2。membersは60人ID別のattending、rating(null/1〜5整数)、igl(yes/no/unknown)、social(required/prefer/none)、friends、note、organization。settingsはsameTeam、pastTeam、sameOrganization、repeat。draftはid・builtAt・teams。historyは確定マッチと評価スナップショット。

JSONは既知ID・人数・重複・値の範囲・履歴・形式を全体検証してから置換する。読み込み前の確認とUndoを用意し、不正ファイルは現在設定を変更せず拒否する。読込は8MB以内、メモ500文字以内、履歴最大2000件。ファイル内の名前や画像URLは採用せず、既知の名簿だけを使う。ユーザー入力はHTMLエスケープする。

保存失敗は表示して書き出しを案内する。既存の破損保存データは黙って上書きしない。同じブラウザの別タブで変更があった場合は通知し、端末間同期とは区別する。

## UI

白いカード、淡い青灰色背景、濃紺文字、所属の差し色。人物アイコン＋名前、戦力点、IGLバッジ。チーム編成・メンバー管理・関係性・履歴の4画面。検索・所属/出欠フィルター。PCは左ナビ、スマホは上ナビ。メンバー表は小さい幅で表内スクロール。色だけに依存しないラベルとキーボード操作、モーション低減に対応する。

ロジック16テスト、構文チェック、人物画像60件のデコード検証。ブラウザで誤パス・正パス、出欠・評価・IGL・関係性編集、59人編成、ペアを2人チームにまとめる調整、手動交換・必須条件違反・Undo、確定・次マッチの履歴反映、保存復元、JSON実書出し・再読込・不正ファイル拒否、PC/スマホ幅を確認。公開URLでの最終確認は公開後に記録する。

## スコープ外・残る確認

## 2026-11-24 5段階評価・公開情報調査・関係性拡張（着手前設計）

本人が60人の公開情報調査と5段階化を依頼。ゆきお/ゆふなの5は本人指定値として採用する。公開APEX実績を根拠に仮評価し、時期・根拠URL・情報不足を表示する。暫定の換算基準は5=元APEXプロ/プレデター、4=マスター、3=ダイヤ、2=確認できる一般経験者（ゴールド/プラチナ等）、1=本人が初心者/ほぼ未経験を明示。不足はnull。IGLは別の具体的根拠なしに推測しない。過去最高は現在ランクとは別で表示する。

過去LTK同チームはLTK1〜4の正規名簿ID/所属から集計。所属15人と同階級5人は区別する。編成の既存LTK4優先とは別に、過去LTK1〜3の同チーム優先、現在の所属組織優先を追加する。個人の必須知り合い指定は最優先のまま。無所属/所属不明という文字列を同一組織として扱わない。公開組織情報は出典付きで、手動編集も可能にする。

保存形式をversion2・別キーltk4-apex-team-builder:v2へ変更する。version1の設定は保持し、読み込み時に1〜10→1〜5の切上げ換算（ceil(value/2)）案を確認してから移行する。既存の確定履歴は10段階の点数を保持し、ratingScale:10で明示。新しい履歴はratingScale:5。既存v1を自動上書きしない。未知の保存形式も拒否する。初版からの未評価者は仮3点と表示する。

新規利用者は出典付き調査データを初期値として使用。既存利用者の評価を調査値で黙って上書きせず、確認付きで未評価の補完/本人指定アンカー5の反映/所属補完を選べるようにする。個別手動編集と調査推定値を区別し、公開値を確定事実扱いしない。主観評価はサイトに同梱する今回の依頼範囲だが、ユーザーのローカル編集内容を公開へ自動送信しない。
