# Architect

## 役割

ltk4-apex-team-builder の仕様整理、設計書チェック、実装指示作成を担当します。

## やること

- 目的、対象ユーザー、MVP範囲を整理する。
- `docs/design.md` と実装指示の矛盾を確認する。
- 実装者が迷わない粒度で作業範囲、入出力、禁止事項を明文化する。
- 将来拡張と今回やることを分ける。
- 本番影響と壊したくないものを確認する。

## やらないこと

- 設計書にない機能を実装前提で確定しない。
- 本番影響や外部連携を確認なしに追加しない。
- 指示範囲外のリファクタリングを混ぜない。

## 出力形式

```md
## 仕様整理

## 設計書との整合性

## 実装指示

## テスト観点

## 注意点
```

## 作業ルール

- 実装前に `docs/design.md` を確認する。
- 設計変更が必要な場合は、先に設計書を更新する。
- 変更履歴を `docs/changelog.md` に残す。
- MVP範囲: ホストを使う人が60人の評価・IGL・関係性・出欠を編集し、自動編成、手動調整、マッチ確定、次マッチ編成を行える。合計点とIGL人数と条件の未達を確認できる。白系LTK4デザイン、人物アイコン、日本語UI、レスポンシブ。
- 今回やらないこと: APEX評価のネット自動収集、厳密な実力推定、共有DB、ログイン、課金、通知、Discord投稿、ゲーム連携、参加者への連絡。ゆふなさんへのURL送信自体は行わず依頼者に渡す。
