# Test Checklist

## 基本動作確認

- [ ] 主要機能が期待どおり動作する。
- [ ] 通常の利用手順でエラーにならない。
- [ ] 利用者向けの手順がREADMEまたは関連ドキュメントから分かる。
- [ ] 実行結果、保存結果、表示結果が目的と一致している。

## 入力確認

- [ ] 必須入力が不足している場合に検出できる。
- [ ] 空文字、長い文字列、特殊文字の扱いが明確である。
- [ ] 不正な入力で処理が壊れない。
- [ ] 入力データの形式が `docs/design.md` と一致している。

## 出力確認

- [ ] 出力先、ファイル名、形式が設計書と一致している。
- [ ] 既存ファイルを不用意に上書きしない。
- [ ] 出力内容に必要な情報が含まれている。
- [ ] 秘密情報や不要な内部情報が出力されない。

## エラー確認

- [ ] 入力不足時に原因が分かるメッセージを表示する。
- [ ] ファイルやディレクトリが存在しない場合に安全に停止する。
- [ ] 権限不足や書き込み失敗時に安全に停止する。
- [ ] エラー後に中途半端な破損データを残さない。

## 既存機能への影響確認

- [ ] 既存の主要機能が変わらず動作する。
- [ ] 既存データ、既存設定、既存出力を壊していない。
- [ ] 変更範囲外のファイルを不用意に変更していない。
- [ ] 設計書の「今回やらないこと」に該当する変更が混ざっていない。

## 外部連携がある場合の確認

- [ ] 接続先、認証情報、権限範囲が明確である。
- [ ] 外部サービス停止時や通信失敗時の挙動を確認した。
- [ ] レート制限、タイムアウト、リトライ方針が明確である。
- [ ] 秘密情報をログや出力に含めない。

## 本番影響がある場合の確認

- [ ] 本番影響の範囲が `docs/design.md` に記載されている。
- [ ] 変更前にバックアップ、復旧方法、停止条件を確認した。
- [ ] 破壊的操作に確認手順がある。
- [ ] リリース後に確認するログや指標が明確である。

## プロジェクト固有チェック

- [ ] MVP範囲に含まれる機能を優先して確認した: ホストを使う人が60人の評価・IGL・関係性・出欠を編集し、自動編成、手動調整、マッチ確定、次マッチ編成を行える。合計点とIGL人数と条件の未達を確認できる。白系LTK4デザイン、人物アイコン、日本語UI、レスポンシブ。
- [ ] 今回やらないことに含まれる機能を実装・テスト対象に混ぜていない: APEX評価のネット自動収集、厳密な実力推定、共有DB、ログイン、課金、通知、Discord投稿、ゲーム連携、参加者への連絡。ゆふなさんへのURL送信自体は行わず依頼者に渡す。
- [ ] 絶対に壊したくないものに悪影響がない: sourcesと既存アプリ、既存の正本・公開サイト。ユーザーが入力した設定を勝手に上書きしない。主観評価や私的関係性を公開ファイル・URLへ含めない。
- [ ] 運用時に確認したいログを確認できる: 60人の一意性、人物画像の妥当性、自動編成の人数と重複、必須条件、処理時間、履歴の二重計上、保存失敗と入力検証、公開URLの応答。
- [ ] 注意点が実装、テスト、運用手順に反映されている: 日本語UTF-8。保存方式・データ構造の提案は本人回答待ち。初期の戦力やIGLや私的な知り合い関係を推測で確定しない。関係性条件が満たせなければ表示し、確定を防ぐ。公開は新規サイトだけ。役割別の確認は記録し、未検証を完了にしない。

## 回帰テスト観点

- [ ] 変更前に動いていた主要フローを再確認した。
- [ ] エラー系、境界値、空データの扱いを確認した。
- [ ] 設定変更や入力仕様変更の影響を確認した。
- [ ] READMEや運用手順と実際の動作が一致している。

## リリース前チェック

- [ ] `docs/design.md` が最新の仕様と一致している。
- [ ] `docs/ai-development-rules.md` のv2ルールと矛盾していない。
- [ ] Codexへの実装依頼が必要な場合、`docs/codex-instruction.md` の見出しを確認した。
- [ ] `docs/codex-report.md` の最新レポートに `codex-meta` が含まれている。
- [ ] `docs/data-schema.md` の `codex-meta` 項目定義と矛盾していない。
- [ ] `docs/changelog.md` に変更内容を記録した。
- [ ] `docs/codex-report.md` に今回の作業レポートを追記した。
- [ ] `docs/progress-rules.md` に従って必須フラグを記録した。
- [ ] 未解決の重大なレビュー指摘がない。
- [ ] 実行したテストと未実施のテストを説明できる。
- [ ] 注意点と次にやるべきことが明確である。
